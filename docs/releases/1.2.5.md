Pi-Bolt 1.2.5 adds offline recovery for installer-created launchers. Version 1.2.4 was not published: the release checks exposed Unix-only assumptions in the doctor test fixture on Windows. This release fixes the fixture without changing doctor's native path formatting or skipping its checks.

### Added

- **`pi-bolt repair`** restores missing or broken installer-owned `pi-bolt` and conditional `pi` launchers from the installed runtime. It works offline without downloading or replacing the runtime, loading extensions, or changing PATH or shell profiles. Real Pi commands and unrecognized files are preserved. Package-manager installations must be repaired through their owning package manager.

### Changed

- **`pi-bolt doctor --offline`** reports launcher problems, suggests the repair command, and distinguishes a missing launcher from its directory being absent from PATH.
- The Linux, Windows, and macOS release jobs run the launcher-repair and doctor regression tests before building artifacts.

### Recovery

```sh
pi-bolt repair
pi --version
```

Run `rehash` in Zsh if it still cannot find a restored command. See [launcher recovery](../HERDR.md#restore-missing-launchers) for custom installation directories and invoking the runtime directly when `pi-bolt` itself is missing.

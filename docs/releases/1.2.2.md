Pi-Bolt 1.2.2 is [1.2.1](1.2.1.md) with the fork's Herdr behavior restored on top of the merge that had replaced it.

### Fixed

- **Herdr restores previous sessions again.** The 1.2.1 merge took upstream's reporter, which identifies the pane's agent as `pi-bolt` and asks Herdr to restore with an explicit `pi-bolt --session` command; stock Herdr does not restore a session from that. The fork's builds report as Herdr's official Pi integration (`herdr:pi`) again without any flag — their engine process is Pi-named by construction — register the session with `pane.report_agent_session`, and leave the restore to Herdr's own canonical `pi --session` plan, which goes through the conditional `pi` shim the installer writes (the compiled build when no Node Pi is installed, Node Pi otherwise). `--herdr-pi` stays as the explicit alias, and a source that reports as plain `pi-bolt` (a source run) still carries the explicit resume command, as upstream's design does.
- **Herdr no longer reports a working agent as blocked.** A UI prompt is not a blocked signal: pi-atelier hosts its sidebar as a persistent overlay for the whole session, so every turn reported blocked. Extensions that wait for the user still say so on the `herdr:blocked` channel, which stays the only blocked source.
